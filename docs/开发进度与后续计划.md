## 4. 已知待复核点（首次编译时优先核对）

> 这些不是确定的缺陷，而是「无法编译验证」情况下的**高风险代码片段**，首次 Sync 后应逐条对照。

| 编号 | 位置 | 关注点 |
| --- | --- | --- |
| C-1 | `data/pagination/…/PaginationEngine.kt` | `TextMeasurer.measure(...)` 在 Compose 1.6/1.7 的参数签名（尤其 `Constraints` 的 `androidx.compose.ui.unit` 包与 `maxLines`）可能与书写不一致 |
| C-2 | 同上 | 由 px 反解回 sp 依赖 `density.density * density.fontScale`；若 `rememberTextMeasurer` 自带 Density 与传入 `LocalDensity.current` 不一致，会导致排版与渲染不符（>1 屏偏差即触发 Gate 2 失败） |
| C-3 | 同上 | 缓存 key 含 `request.content.length` 但不含内容指纹，同章内容变化而长度相同的场景可能命中陈旧分页 → 建议改用 `cheapHash(content)` |
| C-4 | `core/database/dao/KrDatabase.kt` | 实体字段 / 索引 / ForeignKey 与实际 DAO SQL 列名是否逐一匹配（DAO 曾用「列名不一致」理由重写过一次，仍建议用 Room 的编译期校验兜底） |
| C-5 | `core/database/…/KrTypeConverters.kt` | 未被 `@TypeConverters` 显式注册到 Database 上时 Room 会直接编译失败 |
| C-6 | `data/parser/…/EpubParser.kt` | jsoup `dc|title` 命名空间选择器依赖 XML 解析模式；`EmupStructure.opfPath` 已修复但 XML 命名空间前缀写法需实机验证 |
| C-7 | `data/parser/…/PdfParser.kt` | `@Binds fun bindPdfPageRenderer(impl: PdfParser)` 要求 `PdfParser` 可被注入且为 `@Singleton`；同时 `openRenderer` 的 `return@openRenderer` 标签返回需确认无编译歧义 |
| C-8 | `core/datastore/…/JsonSerializer.kt` | DataStore 的 `OkioSerializer` 与 kotlinx-serialization 版本对齐（`kr.serialization` 插件版本需与 `:core:datastore` 实际 usage 一致） |

## 7. 约定提醒（写代码时必须遵守）

- **注释**：所有新文件都要 koroFileHeader 文件头；注释写「为什么」，禁止复述代码。
- **业务规则**：注释特定的东西解释业务妥协（如 `FileArchive.persistUriPermission` 解释为什么必须申请持久化授权）。
- **协程**：禁 `GlobalScope`；大循环插 `ensureActive()`；IO → `IoDispatcher`，分页 → `DefaultDispatcher` + `Mutex`。
- **大文件**：禁 `readText()` / `readBytes()`，一律流式（detekt `ForbiddenMethodCall` 会拦截）。
- **Compose**：参数只传数据 + lambda，动画用 `Animatable` + `graphicsLayer`，列表给稳定 key。
- **文档**：改了设计就要改 `docs/`，然后 `node scripts/build-archive.js` 重新生成根目录合并版与 HTML 版（**不要手改那两个生成产物**）。
